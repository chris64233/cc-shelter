# cc-shelter

管理家庭成员、床位资源和入住安排，支持家庭成员走散后的临时入住、身份核验与安全合并（家庭重聚），
以及家庭在不同安置点之间的整体转移与两阶段交接。

## 主要业务规则

- **整体入住**：家庭全部成员必须安排到同一安置点的同一房间，不允许拆分家庭或部分占床；
  房间剩余床位必须不小于家庭人数，家庭中有成员需要无障碍设施时房间必须支持无障碍。
- **房间选择**：在满足容量和无障碍条件的房间中，按“安置后剩余床位最少、房间编号最小”稳定选择。
- **唯一约束**：家庭号全局唯一，**在住成员**身份标识全局唯一（注册与合并时双重校验）；
  家庭已存在有效入住时整笔拒绝新的入住。
- **幂等**：入住、转移、临时入住、身份核验、退住、合并确认请求必须携带幂等键，合并申请使用合并业务号，
  家庭转移使用外部业务号与交接事件号。
  相同键/业务号 + 相同内容的重放返回首次结果；携带不同内容返回 `409 IDEMPOTENCY_CONFLICT`。
- **并发安全**：所有写事务按“家庭行（按主键升序）→ 申请单行 → 房间行（按主键升序）”统一顺序加悲观写锁
  （`SELECT ... FOR UPDATE`），锁序全局一致，不会死锁或超卖。

### 走散成员临时入住

- 单个走散成员可以**临时家庭**身份登记入住：必须声明原家庭号，成员初始核验状态为 `UNVERIFIED`。
- 临时家庭与正式家庭走不同入住通道（`/api/temporary-check-ins`），互不混用。
- 未完成身份核验的临时成员**不能**被并入正式家庭，创建合并申请时直接拒绝。
- 身份核验事件按幂等键去重，只追加一条 `IDENTITY_VERIFIED` 成员事件，重复核验返回 `409`。

### 安全合并（家庭重聚）

- **两阶段**：先创建合并申请（`PENDING`，冻结参与方名单、目标安置点与期望入住 ID），再确认。
  一个申请可把**多个临时入住**同时并入**一个正式家庭**。
- **确认时重新校验全部条件**：所有成员身份标识在合并范围内唯一、目标房间容量足够、
  无障碍条件满足、`expectedTargetStayId` 与当前有效入住一致；任一不满足整个事务回滚，
  原入住与床位完全不变，申请单保留可在条件满足后重试。
- **一次性原子迁移**：在同一事务内结束正式家庭旧入住与全部临时入住、释放原床位、
  占用目标房间、把全部临时成员以 `VERIFIED` 状态迁入正式家庭。
- **同事务整体换房**：原家庭房间不足时，申请可指定新安置点，整个家庭（含新并入成员）
  在合并事务内一并迁移；容量复核会计入本事务即将释放的床位（含各临时入住的床位）。
- 并发合并、家庭转移与成员退住由统一锁序串行化：不会产生重复成员、双重入住或错误释放床位。

### 跨安置点家庭整体转移（两阶段交接）

当家庭需要整体迁往**另一个安置点**、且目标点要提前预留房间时，走两阶段交接流程
（资源前缀 `/api/transfer-requests`）。它与即时转移（`POST /api/transfers`，当场完成搬迁）互补：
交接流程把“承诺房间”和“实际搬迁”分开，避免家庭到达后无房或来源点提前释放床位。

- **创建申请**（`REQUESTED`，外部业务号 `transferNo` 幂等）：
  - 只面向**正式家庭**；记录来源安置点、目标安置点、目标房间要求（床位数/无障碍）、
    计划到达时间与外部业务号；床位数缺省取冻结成员数，显式要求不得少于成员数。
  - 创建时**冻结**家庭成员清单（成员 ID、身份标识、核验状态、无障碍需求）与当前入住关系
    （来源入住 ID、来源房间）。
  - 以下情形不得发起：存在**未完成的团聚（合并）申请**、成员身份尚未全部确认、
    家庭已经退住（无有效入住）、目标与来源是同一安置点、同一家庭已有一笔活动转移。
- **目标接受**（`REQUESTED → ACCEPTED`）：
  - 目标安置点为完整家庭预留一间满足容量与无障碍条件的房间，房间增加 `reservedBeds`，
    **不释放来源床位**，只形成待交接状态。
  - 一间房在交接完成前只能被一笔转移预留（`reserved_room_id` 唯一约束兜底），
    普通入住按现有多家庭同住规则仍可使用该房间的剩余床位，但容量不足时不得占用。
  - 接受前会重新核对冻结清单；没有合适房间返回 `409 NO_SUITABLE_ROOM`，申请保留可重试。
- **到达确认**（`ACCEPTED → COMPLETED`，交接事件号 `handoverNo` 幂等）：
  - 必须携带与冻结一致的 `expectedOriginStayId`；
  - **一次性原子完成**：结束来源入住并释放来源床位、把目标房间预留转为实际占用、
    建立目标入住、为每个冻结成员追加 `TRANSFERED` 成员事件（家庭关系不变）。
  - 成员退住、家庭合并/迁移与到达确认并发时，**重新核对冻结清单**：
    成员集合、核验状态或来源入住发生任何变化都返回 `409 FROZEN_LIST_CHANGED`/`STALE_STATE`，
    旧确认失败且整笔回滚——不会产生成员留在两处，也不会出现床位已释放但目标入住未建立。
- **拒绝 / 取消 / 超时**：
  - 目标拒绝、家庭取消或超过计划到达时间未交接（`POST /api/transfer-requests/timeouts`）
    都会终结申请（`REJECTED`/`CANCELLED`/`TIMED_OUT`），**释放目标预留并保持来源入住有效**。
  - 家庭退住或发起即时转移时，其活动的交接申请会在**同一事务内自动取消**并释放目标预留。
  - **已完成的转移不能撤销**，只能通过一笔新的反向转移处理。
- **幂等细节**：业务号用于创建，交接事件号用于到达确认；接受/拒绝/取消按“操作 + 业务号”
  独立命名空间做幂等。业务号或交接事件号相同且内容一致时返回原结果，内容不同返回 `409`。

### 家庭转移与团聚流程的关系

- 两条流程都以**正式家庭当前的唯一有效入住**为基准，且都在创建时冻结成员/入住、执行时重新核对，
  由统一锁序串行化，互斥规则如下：
- 家庭存在**未完成团聚申请**时不能发起整体转移（团聚可能整体换房或改变成员）；
  家庭存在**活动转移申请**（`REQUESTED`/`ACCEPTED`）时不能发起团聚。
- 走散成员所在的**临时家庭不能直接转移**：必须先完成身份核验并通过团聚并入正式家庭，
  再以正式家庭为单位整体转移。
- 团聚的“同事务整体换房”解决的是**合并当下**迁入新安置点；两阶段转移解决的是
  **没有合并动作**、家庭提前与目标点预约房间后择日搬迁的场景。
- 转移完成后家庭仍是同一正式家庭，之后仍可正常发起新的团聚或新的转移（含反向转移）。

### 审计与查询

- **入住事件流**（`stay_events`，只增）：`CHECK_IN` / `TRANSFER` / `MERGE` / `TEMP_MERGED` /
  `CHECKOUT`，合并事件带合并业务号，两阶段转移事件带转移业务号与交接事件号。
  原临时入住记录保留为 `ENDED`，不删除。
- **成员事件流**（`member_events`，只增）：`TEMPORARY_CHECK_IN` / `IDENTITY_VERIFIED` /
  `MERGED` / `TRANSFERRED` / `CHECKOUT`，记录身份确认、家庭关系变化与当时所在房间/安置点，
  按序即为该成员的完整房间迁移链。
- **转移查询**：转移进度（状态、两端房间与实时占用/预留快照、冻结成员、各阶段时间）、
  成员交接清单（冻结项与当前在住状态逐项核对）、跨安置点入住时间线。
- **统一错误**：所有错误返回 `{"code", "message", "timestamp"}` 结构的 JSON。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/shelters` | 创建安置点 |
| POST | `/api/shelters/{id}/rooms` | 为安置点添加房间（床位数、无障碍标记） |
| GET | `/api/shelters/{id}/rooms` | 查询安置点各房间占用 |
| POST | `/api/households` | 登记正式家庭及成员 |
| POST | `/api/households/temporary` | 登记临时家庭（临时家庭号 + 申报原家庭号 + 成员） |
| GET | `/api/households/{no}` | 家庭详情（类型、申报原家庭号、成员核验状态） |
| GET | `/api/households/{no}/stay` | 查询家庭当前有效入住 |
| GET | `/api/households/{no}/events` | 查询家庭入住/转移/合并/退住事件流 |
| GET | `/api/households/{no}/timeline` | 跨安置点入住时间线（含转移/交接事件号） |
| GET | `/api/households/members/{identityNo}/events` | 查询成员身份核验、家庭关系与房间迁移链 |
| POST | `/api/check-ins` | 正式家庭整体入住（幂等键 + 家庭号 + 安置点） |
| POST | `/api/temporary-check-ins` | 临时家庭入住（幂等键 + 临时家庭号 + 安置点） |
| POST | `/api/identity-verifications` | 临时成员身份核验（幂等键 + 成员身份标识） |
| POST | `/api/transfers` | 即时家庭整体转移（幂等键 + 目标安置点 + 期望入住 ID，当场完成） |
| POST | `/api/checkouts` | 成员退住、释放床位（幂等键 + 家庭号 + 期望入住 ID） |
| POST | `/api/merges` | 创建合并申请（合并业务号 + 正式家庭 + 临时家庭列表 + 可选目标安置点） |
| POST | `/api/merges/confirm` | 确认合并（幂等键 + 合并业务号 + 期望正式家庭入住 ID） |
| POST | `/api/transfer-requests` | 创建跨安置点转移申请（业务号 + 来源/目标安置点 + 房间要求 + 计划到达时间） |
| POST | `/api/transfer-requests/accept` | 目标安置点接受并预留房间（业务号） |
| POST | `/api/transfer-requests/reject` | 目标安置点拒绝（业务号 + 原因） |
| POST | `/api/transfer-requests/cancel` | 家庭取消转移（业务号 + 原因） |
| POST | `/api/transfer-requests/arrive` | 到达确认、一次性交接（业务号 + 交接事件号 + 期望来源入住 ID） |
| POST | `/api/transfer-requests/timeouts` | 扫描终结已超时的待交接申请并释放预留 |
| GET | `/api/transfer-requests/{transferNo}` | 转移进度与两端房间占用快照 |
| GET | `/api/transfer-requests/{transferNo}/handover` | 成员交接清单与冻结核对结果 |

### 合并请求示例

创建申请（业务号 `MRG-001` 幂等；`targetShelterId` 省略表示并入当前房间，提供则整体迁至新安置点）：

```json
POST /api/merges
{
  "mergeNo": "MRG-001",
  "targetHouseholdNo": "F-2026-001",
  "temporaryHouseholdNos": ["T-77", "T-93"]
}
```

确认合并（条件不满足返回 409，原入住不变；可修正条件后用同一业务号重试）：

```json
POST /api/merges/confirm
{
  "idempotencyKey": "7f3c...",
  "mergeNo": "MRG-001",
  "expectedTargetStayId": 42
}
```

### 跨安置点转移交接示例

创建申请（业务号 `TRF-001` 幂等；`requiredBedCount` 省略时取冻结成员数）：

```json
POST /api/transfer-requests
{
  "transferNo": "TRF-001",
  "householdNo": "F-2026-001",
  "targetShelterId": 7,
  "requiredBedCount": 4,
  "requiresAccessible": true,
  "plannedArrivalAt": "2026-09-30T10:00:00Z"
}
```

目标接受（只预留房间，状态变 `ACCEPTED`）：

```json
POST /api/transfer-requests/accept
{ "transferNo": "TRF-001" }
```

到达确认（交接事件号 `HND-001` 幂等；冻结清单变化或期望入住不符返回 409，整笔回滚）：

```json
POST /api/transfer-requests/arrive
{
  "transferNo": "TRF-001",
  "handoverNo": "HND-001",
  "expectedOriginStayId": 42
}
```

- JDK 21

- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test

测试覆盖（共 55 个）：入住/即时转移场景、临时入住通道隔离、核验幂等、
未核验禁止合并、多临时家庭一次性合并、容量/无障碍/唯一性复核失败整体回滚、
同事务整体换房、退住释放、合并×退住/转移/并发确认的竞争，以及
跨安置点两阶段转移的申请冻结与互斥校验、接受预留与重复预留防护、预留与普通入住容量关系、
拒绝/取消/超时释放且来源入住不变、已完成不可撤销与反向转移、
到达确认×退住/迁移/并发到达的冻结清单复核、交接事件号幂等冲突、
进度/交接清单/时间线查询和完整 HTTP 端到端流程。
