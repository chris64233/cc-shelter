# cc-shelter

管理家庭成员、床位资源和入住安排。

## 主要业务规则

- **整体入住**：家庭全部成员必须安排到同一安置点的同一房间，不允许拆分家庭或部分占床；
  房间剩余床位必须不小于家庭人数，家庭中有成员需要无障碍设施时房间必须支持无障碍。
- **房间选择**：在满足容量和无障碍条件的房间中，按“剩余床位最少、房间编号最小”稳定选择。
- **唯一约束**：家庭号全局唯一，成员身份标识全局唯一；家庭已存在有效入住时整笔拒绝新的入住。
- **幂等**：入住和转移请求必须携带幂等键。相同幂等键 + 相同内容的重放返回首次结果；
  相同幂等键 + 不同内容返回 `409 IDEMPOTENCY_CONFLICT`。
- **并发安全**：入住对家庭行和候选房间行加悲观写锁（`SELECT ... FOR UPDATE`）并复核剩余床位，
  并发入住不会超卖房间。
- **整体转移**：转移在同一事务内先锁定目标安置点的合适房间，再释放原房间；
  目标安置点没有合适房间时整个事务回滚，原入住完整保留。
  请求需携带 `expectedStayId` 防止基于陈旧状态转移；两个并发转移只有一个能成功，
  不会重复释放床位或形成双重入住。
- **事件流**：每次入住和转移追加一条不可变事件（`CHECK_IN` / `TRANSFER`），只增不改。
- **统一错误**：所有错误返回 `{"code", "message", "timestamp"}` 结构的 JSON。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/shelters` | 创建安置点 |
| POST | `/api/shelters/{id}/rooms` | 为安置点添加房间（床位数、无障碍标记） |
| GET | `/api/shelters/{id}/rooms` | 查询安置点各房间占用 |
| POST | `/api/households` | 登记家庭及成员 |
| GET | `/api/households/{no}/stay` | 查询家庭当前有效入住 |
| GET | `/api/households/{no}/events` | 查询家庭入住/转移事件流 |
| POST | `/api/check-ins` | 家庭整体入住（幂等键 + 家庭号 + 安置点） |
| POST | `/api/transfers` | 家庭整体转移（幂等键 + 目标安置点 + 期望入住 ID） |

## 开发环境

- JDK 21
- Spring Boot 4.1.1
- Maven Wrapper 3.9.9
- H2

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test
