# cc-shelter

管理家庭成员、床位资源和入住安排，支持家庭成员走散后的临时入住、身份核验与安全合并（家庭重聚），
以及正式家庭在不同安置点之间的整体转移与交接。

## 主要业务规则

- **整体入住**：家庭全部成员必须安排到同一安置点的同一房间，不允许拆分家庭或部分占床；
  房间剩余床位必须不小于家庭人数，家庭中有成员需要无障碍设施时房间必须支持无障碍。
- **房间选择**：在满足容量和无障碍条件的房间中，按“安置后剩余床位最少、房间编号最小”稳定选择。
- **唯一约束**：家庭号全局唯一，**在住成员**身份标识全局唯一（注册与合并时双重校验）；
  家庭已存在有效入住时整笔拒绝新的入住。
- **幂等**：入住、转移、临时入住、身份核验、退住、合并确认请求必须携带幂等键，
  合并申请使用合并业务号、家庭转移使用转移业务号、到达交接使用交接事件号。
  相同键/业务号 + 相同内容的重放返回首次结果；携带不同内容返回 `409 IDEMPOTENCY_CONFLICT`。
- **并发安全**：所有写事务按“家庭行（按主键升序）→ 房间行（按主键升序）”统一顺序加悲观写锁
  （`SELECT ... FOR UPDATE`），锁序全局一致，不会死锁或超卖。

### 走散成员临时入住

- 单个走散成员可以**临时家庭**身份登记入住：必须声明原家庭号，成员初始核验状态为 `UNVERIFIED`。
- 临时家庭与正式家庭走不同入住通道（`/api/temporary-check-ins`），互不混用。
- 未完成身份核验的临时成员**不能**被并入正式家庭，创建合并申请时直接拒绝。
- 身份核验事件按幂等键去重，只追加一条 `IDENTITY_VERIFIED` 成员事件，重复核验返回 `409`。

### 安全合并（家庭重聚）

- **两阶段**：先创建合并申请（`PENDING`，冻结参与方名单、目标安置点与期望入住 ID），再确认。
  一个申请可把**多个临时入住**同时并入**一个正式家庭**。
- **确认时重新校验全部条件**：所有成员身份标识在合并范围内唯一、目标房间容量足够、
  无障碍条件满足、`expectedTargetStayId` 与当前有效入住一致；任一不满足整个事务回滚，
  原入住与床位完全不变，申请单保留可在条件满足后重试。
- **一次性原子迁移**：在同一事务内结束正式家庭旧入住与全部临时入住、释放原床位、
  占用目标房间、把全部临时成员以 `VERIFIED` 状态迁入正式家庭。
- **同事务整体换房**：原家庭房间不足时，申请可指定新安置点，整个家庭（含新并入成员）
  在合并事务内一并迁移；容量复核会计入本事务即将释放的床位（含各临时入住的床位）。
- 并发合并、家庭转移与成员退住由统一锁序串行化：不会产生重复成员、双重入住或错误释放床位。

### 跨安置点家庭整体转移（申请 → 接受 → 到达交接）

正式家庭可在**不同安置点之间**做有预约的整体转移，分三阶段（`/api/transfer-applications`）；
即时、无预约的同构转移仍走 `POST /api/transfers`（一步完成）。

1. **创建申请**（`REQUESTED`，转移业务号幂等）：以一个正式家庭为单位，记录来源安置点、
   目标安置点、目标房间要求（可指定房间号，省略则由目标按统一规则选房）、计划到达时间和外部业务号。
   创建时**冻结**家庭成员清单（身份标识/年龄/无障碍/核验状态快照）与当前入住关系（入住 ID、房间）。
   - 存在**未完成的团聚（合并）申请**、成员**身份尚未确认**（`UNVERIFIED`）、
     或家庭**已退住/无有效入住**时，直接拒绝发起。
   - 同一家庭同时只能有一笔活动转移（活动槽位表 + 家庭行锁双重保证）。
2. **目标接受**（`ACCEPTED`）：目标安置点为**完整家庭**预留一间满足容量和无障碍条件的房间。
   - 接受**只形成待交接状态**：预留计入容量但**绝不提前释放来源床位**，家庭仍住在来源房间。
   - **同一目标房间不能被两个家庭重复预留**（预留表 `room_id` 唯一约束 + 房间行锁内排除已预留房间），
     即使该房间物理床位仍有余量。接受失败（如容量不足）只回滚接受事务，可在扩容后重试。
3. **到达确认**（`ARRIVED`，交接事件号幂等）：在家庭行锁内**重新核对冻结清单**——
   来源入住仍有效、期望入住 ID 一致、冻结成员逐项与当前在住成员完全一致；
   随后在**同一事务内一次性**结束来源入住、启用目标入住、迁移全部成员并写入审计事件。
   - 成员退出、家庭合并与到达确认并发时，由统一锁序串行化，败者基于重核失败：
     成员或入住关系有任何变化，旧的到达确认返回 `409 FROZEN_LIST_CHANGED` / `STALE_STATE`，
     **不会**产生成员留在两处，也**不会**出现来源床位已释放但目标入住未建立的中间状态。
- **异常终态**：目标**拒绝**、家庭**取消**或**超时**（过了计划到达时间）都释放目标预留，
  来源入住始终保持有效；家庭可随后重新发起转移。
- **不可撤销**：已经完成（`ARRIVED`）的转移不能撤销，只能通过一笔新的**反向转移**处理。
- **幂等**：创建按转移业务号；接受/拒绝/取消/超时按幂等键；**到达交接按交接事件号**——
  相同交接事件号且内容一致返回首次交接结果，内容不同返回 `409 IDEMPOTENCY_CONFLICT`。
- **超时**：单笔 `POST /api/transfer-applications/expire`（未到时限返回 `409 TRANSFER_NOT_DUE`）；
  批量 `POST /api/transfer-applications/expire-due` 扫描所有过时限的活动转移，逐笔独立事务释放预留。

### 家庭转移与家庭重聚（团聚）的关系

二者是面向**不同场景**的两条通道，共享同一套家庭/床位/锁序基础设施，但业务上互斥与协同如下：

- **家庭重聚（合并）**解决“走散的**临时家庭**重新并回**正式家庭**”，可能伴随正式家庭换房，
  参与方是 1 个正式家庭 + N 个已核验的临时家庭，走 `/api/merges`。
- **家庭转移**解决“一个**完整正式家庭**在两个安置点之间的有预约整体搬迁”，
  不改变家庭成员构成，走 `/api/transfer-applications`。
- 发起转移时若该家庭（作为正式目标或临时参与方）**存在未完成团聚申请则拒绝**；
  反过来，转移已经活动期间不禁止创建团聚申请——当“合并确认”与“到达确认”真正并发时，
  由两者事务内的期望入住/冻结清单重核决定唯一胜者，保证不产生重复成员或双重入住。
- 走散成员应先完成临时入住、身份核验并安全合并回正式家庭（团聚），
  待家庭重新完整后再以正式家庭为单位发起跨安置点转移。

### 审计与查询

- **入住事件流**（`stay_events`，只增）：`CHECK_IN` / `TRANSFER` / `MERGE` / `TEMP_MERGED` /
  `CHECKOUT`，合并事件带合并业务号、三阶段转移事件带转移业务号。原临时入住与来源入住记录保留为
  `ENDED`，不删除。
- **成员事件流**（`member_events`，只增）：`TEMPORARY_CHECK_IN` / `IDENTITY_VERIFIED` /
  `MERGED` / `TRANSFER` / `CHECKOUT`，记录身份确认、家庭关系变化（从哪个临时家庭并入哪个正式家庭）
  及当时所在房间/安置点（转移事件同时记录来源与目标房间），按序即为该成员的完整房间迁移链。
- **转移查询**：单笔转移进度（含冻结成员清单）、两端房间占用（目标房间含“已预留床位/可用床位”）、
  成员交接清单（`FROZEN` / `HANDED_OVER` / `DEPARTED`）、家庭的跨安置点入住时间线与全部转移记录。
- **统一错误**：所有错误返回 `{"code", "message", "timestamp"}` 结构的 JSON。

## API 概览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/shelters` | 创建安置点 |
| POST | `/api/shelters/{id}/rooms` | 为安置点添加房间（床位数、无障碍标记） |
| GET | `/api/shelters/{id}/rooms` | 查询安置点各房间占用 |
| POST | `/api/households` | 登记正式家庭及成员 |
| POST | `/api/households/temporary` | 登记临时家庭（临时家庭号 + 申报原家庭号 + 成员） |
| GET | `/api/households/{no}` | 家庭详情（类型、申报原家庭号、成员核验状态） |
| GET | `/api/households/{no}/stay` | 查询家庭当前有效入住 |
| GET | `/api/households/{no}/events` | 查询家庭入住/转移/合并/退住事件流 |
| GET | `/api/households/members/{identityNo}/events` | 查询成员身份核验、家庭关系与房间迁移链 |
| POST | `/api/check-ins` | 正式家庭整体入住（幂等键 + 家庭号 + 安置点） |
| POST | `/api/temporary-check-ins` | 临时家庭入住（幂等键 + 临时家庭号 + 安置点） |
| POST | `/api/identity-verifications` | 临时成员身份核验（幂等键 + 成员身份标识） |
| POST | `/api/transfers` | 即时家庭整体转移（幂等键 + 目标安置点 + 期望入住 ID，一步完成） |
| POST | `/api/checkouts` | 成员退住、释放床位（幂等键 + 家庭号 + 期望入住 ID） |
| POST | `/api/merges` | 创建合并申请（合并业务号 + 正式家庭 + 临时家庭列表 + 可选目标安置点） |
| POST | `/api/merges/confirm` | 确认合并（幂等键 + 合并业务号 + 期望正式家庭入住 ID） |
| POST | `/api/transfer-applications` | 创建跨安置点转移申请（转移业务号 + 目标安置点 + 目标房间要求 + 计划到达时间 + 外部业务号） |
| POST | `/api/transfer-applications/accept` | 目标接受并预留房间（幂等键 + 转移业务号） |
| POST | `/api/transfer-applications/arrive` | 到达确认/交接（**交接事件号** + 转移业务号 + 期望来源入住 ID） |
| POST | `/api/transfer-applications/reject` | 目标拒绝（幂等键 + 转移业务号 + 原因） |
| POST | `/api/transfer-applications/cancel` | 家庭取消（幂等键 + 转移业务号） |
| POST | `/api/transfer-applications/expire` | 单笔超时（幂等键 + 转移业务号） |
| POST | `/api/transfer-applications/expire-due` | 批量超时所有过时限的活动转移 |
| GET | `/api/transfer-applications/{transferNo}` | 转移进度（含冻结成员清单） |
| GET | `/api/transfer-applications/{transferNo}/rooms` | 两端房间占用（目标含预留/可用床位） |
| GET | `/api/transfer-applications/{transferNo}/handover` | 成员交接清单 |
| GET | `/api/transfer-applications/households/{no}` | 家庭的全部转移记录 |
| GET | `/api/transfer-applications/households/{no}/timeline` | 家庭跨安置点入住时间线 |

### 合并请求示例

创建申请（业务号 `MRG-001` 幂等；`targetShelterId` 省略表示并入当前房间，提供则整体迁至新安置点）：

```json
POST /api/merges
{
  "mergeNo": "MRG-001",
  "targetHouseholdNo": "F-2026-001",
  "temporaryHouseholdNos": ["T-77", "T-93"]
}
```

确认合并（条件不满足返回 409，原入住不变；可修正条件后用同一业务号重试）：

```json
POST /api/merges/confirm
{
  "idempotencyKey": "7f3c...",
  "mergeNo": "MRG-001",
  "expectedTargetStayId": 42
}
```

### 家庭转移示例

创建申请（`targetRoomNumber` 省略表示由目标按统一规则选房；此时冻结成员与来源入住）：

```json
POST /api/transfer-applications
{
  "transferNo": "TRF-2026-0007",
  "householdNo": "F-2026-001",
  "targetShelterId": 12,
  "targetRoomNumber": 3,
  "plannedArrivalAt": "2026-10-02T08:00:00Z",
  "externalBusinessNo": "BUS-EXT-55881"
}
```

目标接受（预留房间、来源床位不变）与到达交接（按交接事件号幂等）：

```json
POST /api/transfer-applications/accept
{ "idempotencyKey": "acc-key-1", "transferNo": "TRF-2026-0007" }

POST /api/transfer-applications/arrive
{ "handoverNo": "HOV-88900", "transferNo": "TRF-2026-0007", "expectedOriginStayId": 42 }
```

## 本地运行

启动服务：

    ./mvnw spring-boot:run

运行测试：

    ./mvnw clean test

测试覆盖（共 58 个）：入住/即时转移原有场景，临时入住通道隔离、核验幂等、
未核验禁止合并、多临时家庭一次性合并、容量/无障碍/唯一性复核失败整体回滚、
同事务整体换房、退住释放、合并×退住/转移/并发确认的竞争，以及完整 HTTP 端到端流程；
家庭转移覆盖：申请冻结与发起拦截（未完成团聚/身份未确认/已退住/一户一笔活动转移）、
接受预留（不释放来源床位、容量不足可重试、指定房间、同一房间不可重复预留）、
到达原子切换两端入住与全部成员迁移、成员退出/退住/合并与到达确认并发的冻结清单重核、
交接事件号幂等与内容冲突、拒绝/取消/超时（单笔+批量）释放预留且来源有效、
完成后只能反向转移、即时转移在活动转移期间被拦截、四类查询，以及完整 HTTP 三阶段流程。
